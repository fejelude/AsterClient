# Privacy and input behavior

The native app observes Minecraft's verified Microsoft Store package family/version/architecture, window identity, foreground state and cursor capture. On the single supported executable hash, it loads its accompanying `AsterBridge.dll` into that Minecraft process through the normal Windows loader. The adapter reads local actor, target, camera and timing state and applies enabled effects through verified native callbacks or owned component fields. It does not inspect other applications' documents or capture the screen.

The adapter is restricted to Store x64 build `1.26.6005.0`, with an exact SHA-256 check before connection. It does not elevate, install a driver, change security settings or attempt an anti-cheat bypass. A running client owns one adapter session; heartbeat, foreground, world generation, local actor and native capture gates stop effects when the session becomes invalid. The app restores its owned timer/FOV values and detaches on normal exit.

Low-level Windows mouse and keyboard hooks keep current physical button/key states and short-lived keydown events needed for movement, optional binds and capture controls. Injected mouse/movement input is rejected to prevent feedback. External F8/F9 commands are accepted for operator testing; the app's own marked input is always excluded. Events are drained in the main loop and discarded outside the app/game focus context. No typed text or input history is written to disk or diagnostics.

Automation is off on a fresh profile, requires an explicit F8 in the game, and pauses on focus loss, game exit, cursor release, Enter/T/Escape/slash, F9, dependency failure or configured license loss. The app releases synthetic movement keys it owns, preserving physical holds. S-Tap temporarily suppresses Forward and restores it only while that physical key remains held in the same focused captured world. A final foreground check precedes each synthetic key press; Windows focus checking and SendInput delivery cannot be atomic.

Requested clicks, native queued actions, accepted native callbacks, and fallback Windows delivery counters are separate. Native attack acceptance does not establish server damage. The optional QA pack independently counts actual hits/damage/block events in a disposable world; it is not installed by the client or required for normal use. Swapped mouse buttons are logical streams; physical swapped-device behavior needs separate validation.

Settings, local background copies and bounded logs remain in `%APPDATA%\AsterClient`. The event log rotates at 2 MiB and keeps one prior file. Each running app also keeps the most recent 200 events in memory. Reports omit personal paths, process IDs, usernames, device identifiers, tokens and purchase keys. Copy Report copies only the exact visible preview to the clipboard. It never uploads it.

Only explicit background-image loading, own-license requests and own signed-update checks use the network. There are no built-in telemetry, Nitro, Discord, advertising or analytics endpoints. HTTPS certificates are validated normally. The only HTTP exception is explicit local development at `127.0.0.1`; redirects are refused. Network work does not block rendering.

The optional license service stores hashes of purchase/access/refresh tokens, licenses and nonce replay records. It does not collect a hardware fingerprint. The client stores its refresh session and signed offline entitlement in Windows Credential Manager. Purchase keys are not saved. Entitlements have a 15-minute online window and at most 24 hours of signed offline grace, bounded by subscription expiry. Revocation is enforced when the service is reachable; offline grace necessarily cannot learn a new server revocation immediately.

To remove the app, quit it and remove its portable folder. No service, startup item, scheduled task, driver, firewall rule, certificate trust or antivirus exclusion is installed. User preferences and own-service credentials are retained unless the user explicitly removes them. Use Plugs > Forget Local Session before removal to erase the current service credential. Previous service/public-key combinations have distinct vault targets and may be removed manually in Windows Credential Manager by their `AsterClient/license/` prefix.

The adapter keeps its DLL and shared session file in the Minecraft package's `LocalState\AsterBridge` folder. These are Aster-owned files and can be removed after both apps have stopped. Normal app operation never edits world files or Minecraft's options. QA fixtures, world changes and local content logging described in the validation report are explicit development tests performed separately.
