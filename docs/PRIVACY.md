# Privacy and input behavior

The native app observes the Minecraft process name, its verified Microsoft Store package family/version/architecture, its window identity, and whether it is foreground/capturing the cursor. It does not read or write game memory, inspect worlds, send game packets, inject a DLL, inspect other applications' documents, or capture the screen.

Low-level Windows mouse and keyboard hooks keep current physical button/key states and short-lived keydown events needed for movement, optional binds and capture controls. Injected events are rejected. Events are drained in the main loop and discarded outside the app/game focus context. No typed text or input history is written to disk or diagnostics. This is an explicit physical-input implementation, not a key logger.

Automation is off on a fresh profile, requires an explicit physical F8 in the game, and pauses on focus loss, game exit, cursor release, Enter/T/Escape/slash, F9, dependency failure or configured license loss. The app releases only synthetic keys it owns, avoiding physical keys the user still holds. Mouse clicks are complete up/down/up sequences; partial send failure triggers a release and pause. Global SendInput cannot make focus checking and delivery one atomic OS operation; a final foreground check immediately precedes every press. Native fixture tests confirm delivery/cancellation, not Minecraft behavior.

Windows input delivery counters are separate from requested clicks. Minecraft acknowledgments are unavailable and represented as null/unavailable, never inferred from SendInput success. The supported input research build is a candidate for private-world testing, not a claim of in-world acceptance. Swapped mouse buttons are reported as logical left/right streams; physical swapped-device behavior needs manual validation.

Settings, local background copies and bounded logs remain in `%APPDATA%\AsterClient`. The event log rotates at 2 MiB and keeps one prior file. Each running app also keeps the most recent 200 events in memory. Reports omit personal paths, process IDs, usernames, device identifiers, tokens and purchase keys. Copy Report copies only the exact visible preview to the clipboard. It never uploads it.

Only explicit background-image loading, own-license requests and own signed-update checks use the network. There are no built-in telemetry, Nitro, Discord, advertising or analytics endpoints. HTTPS certificates are validated normally. The only HTTP exception is explicit local development at `127.0.0.1`; redirects are refused. Network work does not block rendering.

The optional license service stores hashes of purchase/access/refresh tokens, licenses and nonce replay records. It does not collect a hardware fingerprint. The client stores its refresh session and signed offline entitlement in Windows Credential Manager. Purchase keys are not saved. Entitlements have a 15-minute online window and at most 24 hours of signed offline grace, bounded by subscription expiry. Revocation is enforced when the service is reachable; offline grace necessarily cannot learn a new server revocation immediately.

To remove the app, quit it and remove its portable folder. No service, startup item, scheduled task, driver, firewall rule, certificate trust or antivirus exclusion is installed. User preferences and own-service credentials are retained unless the user explicitly removes them. Use Plugs > Forget Local Session before removal to erase the current service credential. Previous service/public-key combinations have distinct vault targets and may be removed manually in Windows Credential Manager by their `AsterClient/license/` prefix.
